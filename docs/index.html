sop-knowledge-worlds

Reusable knowledge worlds for sopworld: schemas and instances in SOP Lang, loaded by applications on demand.

Each world is a sopworld module named k.<world> (its schema: types, slots, rules and soft rules) plus small shards of facts. Everything is SOP Lang and English; every fact names its source in core.source. An application loads a schema as a module of its own world and tells only the shards that the words of the current message point to.

Files

  • worlds/index.json: the catalog: version (pin it and cache by it), sopworld (the sopworld commit everything was validated with), and per world its schema, exports, depends, shards (path, wires, bytes, keys, sources, license, nc for non-commercial terms, warnings), sources and licenses.
  • worlds/vocab.json: an English lemma mapped to the ids of the shards where it matters.
  • worlds/vocab-kinds.json: the same, grouped by what the word names there (a river, a body part, a key), so a reader can skip kinds it cannot resolve.
  • worlds/k.<world>/schema.sop, worlds/k.<world>/shards/*.sop and worlds/k.<world>/WORLD.md.

The drawable objects of k.objects can be browsed in the gallery: every object with its preview, a search box, and the source and licence of each.

The faces of k.faces (presets, expressions, random combinations, and every variant with its slot and features) can be browsed in the faces gallery.

The scenes of k.scenes, each composed into a picture from its facts and the object drawings, are in the scene previews.

Use from an application

Fetch the catalog, fetch a schema and the shard that a word points to, load them into a sopworld World, and ask. The library of the world must hold the schema of every world listed in depends too.

import { World } from './sopworld.mjs';   // sopworld 0.52.0: the commit in catalog.sopworld

const base = 'https://ml-circuits-research.github.io/sop-knowledge-worlds/worlds/';
const get = async (path) => {
  const r = await fetch(base + path);
  if (!r.ok) throw new Error(`${path}: ${r.status}`);
  return r;
};

const catalog = await (await get('index.json')).json();   // pin catalog.version, cache by it
const vocab = await (await get('vocab.json')).json();

// The schema of a world, and those it depends on, as modules of the library.
const library = {};
const addSchema = async (id) => {
  const entry = catalog.worlds.find((w) => w.id === id);
  if (library[id]) return entry;
  library[id] = await (await get(entry.schema)).text();
  for (const dep of entry.depends) await addSchema(dep);
  return entry;
};
const world = await addSchema('k.commonsense');

const w = new World({ library });
w.use('k.commonsense');   // or, in the application's own matrix: @app core.module name=app imports=k.commonsense

// Only the shards that the words of the message point to. (A word for a type or a key of a world points to the
// world's schema path instead, e.g. vocab['capital'] is ['k.geo/schema.sop']: that world is relevant.)
for (const id of vocab['fish'] ?? []) {
  const shard = world.shards.find((s) => s.id === id);
  if (shard) w.tell(await (await get(shard.path)).text());
}

const answer = w.query({ type: 'k.commonsense.thing', where: { name: 'fish' }, seek: 'at' });
console.log(answer.status, answer.value);   // supported water

// Soft knowledge: advice after acting, never a refusal.
const r = w.tell('@p1 k.commonsense.placed thing=fish at=sky scene=s1', { ns: 'scene' });
console.log(r.ok, r.issues.map((i) => i.why));   // true, [ 'A fish is usually in water, not in the sky.', ... ]
// The advice does not change what the world knows.
console.log(w.query({ type: 'k.commonsense.thing', where: { name: 'fish' }, seek: 'at' }).status);   // supported

The contract is in PLAN.md §2 of the repository. Facts can also be given to a world as a fact provider (new World({ facts })) instead of being told. Knowledge types are shared=true, so facts the application tells in its own namespace are joined with them.

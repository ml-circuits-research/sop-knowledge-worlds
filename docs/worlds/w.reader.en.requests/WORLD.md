# Frame-to-request graph declarations

This opt-in module records graph interpretations of four published frame licences: create, remove, resultative property change and spatial placement. The declarations are hand-authored joins to exact frame-role sources, not new vocabulary or sentence patterns. `mapping` selects a licence; `component` names a target, predicate or relation contribution. The consumer validates every `grounded_by` source and every role before expanding graph templates. `metadata` retains structural evidence paths without giving them semantic effect. `relation` admits the complete published preposition family marked `space=static` or `space=direction`, retaining each source identity and canonical `rel` value. Aliases with the same canonical relation retain an explicit spatial `basis_id`; source records with unresolved notes are excluded. In particular, a source explicitly marked as only part of a multiword preposition does not license its fragment as a complete preposition. Prepositions without that spatial declaration are not automatically spatial predicates.

Target mode remains the explicit `w.reader.en.frames.role.target_mode`. An existing target's neutral qualifier selects its referent and becomes an assumption under `target.selector`; the same qualifier on a new target describes the desired result. This interpretation does not change the qualifier's concept, value, polarity or source range. Resultative predicates remain separate from subject qualifiers. Relation marker and goal stay distinct even though both source roles map to semantic `place`. The relation concept is grounded in `k.attributes.attribute.place`; its canonical relation token comes from the admitted preposition source, not an adapter translation table.

Creation/removal do not invent an existence concept or an occurrence constraint. The source frame act, explicit target mode and optional qualifier already form a valid request. Lifecycle verification requires separate complete native observations and explicit host expectations. The graph declarations do not claim any operation has run or succeeded.

Increment remains without a graph mapping: its current phrase profile does not yet supply quantity/head records and the necessary unit/baseline/anchor semantics are not established. Questions, quantified NPs, conjunction, request dependencies and dialogue-context references likewise need declared constructions and bindings. They must remain unresolved rather than be interpreted using punctuation splitting, act-name heuristics or assumed numeric units. These are shared grammar/data obligations across applications.

Runtime consumers require the published phrase profile, frame v2, general frame-to-request compiler and standard request serializer. The old preview overlay is unchanged. Data tests establish source joins and validation only; executable reader coverage is tested separately in the library against the published knowledge pin. This module is not a semantic assessment or English coverage score.
